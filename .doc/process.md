## 移植RT-Thread Nano 到 STM
---
* Clang编译器，将应用代码经过预编译-编译-汇编-链接之后，生成可调试.elf文件。但在main函数中使用操作系统调度级延时函数rt_thread_mdelay()，
clang编译器默认不会把main函数当成单独一个线程，main在此时只是裸机环境，系统上电之后，没等操作系统反应，延时函数就调用，线程挂起，但此时
操作系统还没起来，所以出现了hard_fault_exception错误。
* 这时我们需要修改启动汇编文件，把函数变为先进入entry()线程，在去入口（entry）然后在进入board.c 中初始化rt_hw_board_init()，以及HAL_init
还有系统时钟configuration，接下来启动系统OS调度，系统会自动创建一个main线程，然后在此线程里面去运行main主函数。

 ### CAN收发（异步通信-一个码元细分时间片（同步段+相位缓冲段1+相位缓冲段2））
 1. 总线两端接120电阻（CAN_H和CAN_L之间相当于60欧），阻抗匹配消除振铃，减少寄生电容。
 2. 异步通信，长时间维持电平状态容易错误，没有跳变，同步段无法起作用。采取位填充（BP），若五个bit后电平没有发生改变，则自动插入一个相反电平的bit来维持同步段
 3. 总线仲裁，误码校验（crc）
 4. can通信帧（数据帧-遥控帧-错误帧-过载帧-帧间隔）。标准数据帧格式（比较复杂）https://github.com/yssickjgd/robowalker_train/blob/main/01_electrical/03_motor_control/02_test_can/test_can.xlsx
 5. 滤波器与掩码：配置ID_FILTER和MASK，如果接收0x41，配置滤波器filer为0x41，mask全是1进行按位与，得到的结果和filter一样，则表示可以接收
 6. PG1~8 led 推挽输出（push输出高电平，pull拉低，都是通过mos和电源相连），开漏（“0”为拉低，“1”为高阻态需上拉，适用iic总线通信）
 7. can1挂在apb1，参数设置-预分频（1M波特率，每个bit时间就是1000ns，预分频9的话，时间片为200ns，相当于一个bit有5个时间片，同步段一般占一个，剩下的分配相位缓冲段1和相位缓冲段2，采样时间点夹在相位段之间，并且应该在单bit持续时间的50%到80%之间）
 8. automatic bus-off 总线不稳定发生掉线，自动重连。automatica retransmission 数据被总线仲裁掉，自动重发。**设置can工作模式（静默回环）**，设置can接收中断
 9. 位域打包（将多个功能配置打包进一个8bit字节中，读取时在解包）解决同时传递多个配置参数，函数括号内冗长的问题。
 10. 无符号整数（uint8_t uint16_t uint32_t）溢出会绕回不会报错，1111 1111 自增的话 1 0000 0000 多余的1会被丢弃
 11. 开发板需要5v供电，使用下载器的3.3v会导致收发器不工作，CAN初始化时，会检查RX引脚是否进入空间状态，10ms内没有接收到11个高电平，会初始化失败，需要上拉RX引脚

 ### M3508 + C620 CAN
 1. 24V控制PMOS引脚，引脚为PH2~PH5，高电平供电（引脚避免悬空）
 2. 结构体 位域 uint8_t mychar:3 （内存只占用一个字节中的三位，不适用于操作寄存器，因为端序不同，你不能确定从左端开始还是从右端开始）
 3. typedef void (*CAN_Call_Back)(Struct_CAN_Rx_Buffer *); typedef <老别名> <新别名>  （在遇到指针和数组的情况下，变量名要放在中间）。函数指针名为CAN_Call_Back。被typedef修饰后，变成了类型名
 4. int16_t 塞进 data[0] , 先将高位塞进data[0], data[1]会自动丢弃高位，分两部分存放
 5. CAN1外部物理接口复用在PD0/PD1接口上，静默回环收发复用的是PB8/PB9接口（内部引脚复用，没有引出外部接口）
 6. 标准can单帧长度大概在108bit，如果按1khz传输，波特率是1M，相当于传输一帧数据需要108bit/1M=0.108ms，1ms只能在can总线（串行，一帧一帧传送）上传输9帧数据。4个电机控制4帧，反馈4帧，就已经把带宽给占满了，只能使用can2.（建议总线负载不超70，否则容易发生仲裁碰撞）。 
 7. c语言中面向对象--can有多个接口以及对应的回调函数，以及多个串口都有一些相同的对象比如（rx_buf,rx_size,callback,handler等等）。可以使用Struct将特性封装，然后实例化对象调用。在面向对象的思想中，“状态（变量）应该封装在对象内部。
 8. UART8_Tx_Data[i + 1] = *((char *)(&tmp_data) + i);      //  (char *)(&tmp_data) : 一串连续的长度为1的字符数组，并且不会破坏数值。serialplot按照float格式读取，判断完帧头直接读取四个字节，然后强转 float data = *(float *)(rec_data)。
 9. c实现多态（同一个接口，不同的对象调用实现不同的函数功能）--通常使用显示结构体+函数指针实现。 c实现重载（同名函数，不同参数），好处是如果要实现printfint,printfloat，只需要printf(100),printf(3.14)，不需要为一个功能去写多个函数。使用_Generic去实现，底层设置多个不同命函数，然后在用宏包装，根据传入的类型自动转换函数。
 10. uint8_t *Rx_Data = Rx_Buffer->Data; 这里的Rx_Data是指针变量，代表内存的首地址，拿到内存的首地址可以当成数组使用(Rx_Data[0],Rx_Data[1]....)。uint8_t *Rx_Data[] = Rx_Buffer->Data; 这个代表声明一个指针数组，里面的元素全部是uint8_t *类型指针，拿单个地址去赋值许多地址数据所以报错。
 11. 联合体（共享同一块内存）可以用来拆分float类型，用float类型写进去，用uint8_t类型读出来。--类型双关。只有整型数据（int/uint）可以使用移位>> 然后& 。float无法使用>> 去提取数据，只能使用联合体共享内存
 12. 初始化motor参数（可拓展为一次初始化六个电机），将电机id存入电机指针数组（防止接收中断时判断rx_buff太过冗长），设置电机管理表（管理不同电机的rx_can_id和tx_can_id）， 
 13. 只要一个变量参数在程序运行整个期间值都不会发生变化，那么就要加上const，一是因为安全，有物理级别的防擦写保护（变量烧写在flash中而不是在内存中），二是const可以节省内存，如果不加const，上电初始化过程中会将变量存储在栈上。
 14. .h 只负责声明，不负责创建（分配内存），const Motor_Config_t Motor_Config_Tanle[MAX_MOTORS]在.c文件中创建内存地址，在.h中extern声明，如果不在.h中声明，在别的文件比如main.c或者motor.c中使用就分别要加extern 非常繁琐，如果在.h中提前extern声明，那么在别的.c中直接使用就可以。如果在.h中定义变量的话，所有#include .h文件的.c文件在预编译时候都会把.h文件复制一份，最后链接的时候编译器会发现有多个相同的定义，如果在.c中定义，.h中声明的话就不会重复定义。
 15. PI = 3.1415926....在系统中被认为double类型，target_omega 为float 判断 target_omega == 50.0f * PI , 右边为double类型，左边为float类型，double强转为float类型，末尾精度会被舍弃，不可能相等。
 16. 串级pid--（角度环输出作为速度环输入） 前馈相当于是给系统增加了一个提前量，提高系统的响应速度。 math库（sin函数使用的是double双浮点类型，sinf函数使用的是单浮点类型,可使用单片机内部的FPU）
